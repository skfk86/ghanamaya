# غنماية — المرحلة الأولى (الأساس)

تسجيل الدخول (Google + إيميل)، إكمال الملف، الحساب الهجين (مشترٍ ← بائع)، قواعد الأمان، دالة الأدمن، والبناء التلقائي للـ APK.

## الملفات
| الملف | الوظيفة |
|---|---|
| `www/index.html` | التطبيق كاملاً (ملف واحد) |
| `firestore.rules` | قواعد أمان Firestore |
| `api/set-admin.js` | دالة Vercel لمنح صلاحية الأدمن |
| `capacitor.config.json` | إعداد Capacitor (`com.ghanamaya.app`) |
| `.github/workflows/android.yml` | بناء APK تلقائياً عند كل push |

## خطوات الإعداد (مرة واحدة)

### 1. Firebase Console
1. **Authentication ← Sign-in method:** فعّل Email/Password و Google.
2. **Firestore Database:** أنشئها بمنطقة `eur3`.
3. **Project settings ← Add app ← Android:** الحزمة `com.ghanamaya.app`، ونزّل `google-services.json`.

### 2. التوقيع (تلقائي)
المفتاح محفوظ في سر GitHub `KEYSTORE_BASE64` (base64) وكلمة سره في `KEYSTORE_PASSWORD`، ولا يوجد في المستودع.
أضف هاتين البصمتين في Firebase ← إعدادات تطبيق Android ← Add fingerprint، ثم نزّل `google-services.json` وضعه في جذر المستودع:
```
SHA1:   E5:A5:BF:85:21:C9:5D:C2:E0:6E:1C:A6:F7:0A:2A:03:D3:04:A6:E0
SHA256: 98:36:D4:4A:17:29:E2:02:18:47:DC:44:84:69:DA:4A:D9:C6:C0:DE:A5:CD:31:22:32:F9:AF:5B:F2:D2:A8:FA
```
**المستودع يجب أن يبقى خاصاً**، واحتفظ بنسخة من المفتاح وكلمة سره خارج GitHub: نفس المفتاح سيُستخدم لرفع التطبيق على Google Play.

### 3. نشر قواعد الأمان
انسخ محتوى `firestore.rules` إلى Firebase ← Firestore ← Rules ← Publish.
(أو: `npm i -g firebase-tools && firebase deploy --only firestore:rules --project ghanamaya-4e639`)

### 4. Vercel (رفع الصور + الأدمن)
1. اربط المستودع بمشروع Vercel جديد.
2. Firebase ← Project settings ← Service accounts ← Generate new private key.
3. في Vercel ← Environment Variables:
   - `FIREBASE_SERVICE_ACCOUNT` = محتوى ملف JSON كاملاً
   - `ADMIN_SETUP_SECRET` = كلمة سر عشوائية طويلة (32 حرفاً فأكثر)
   - `IMAGEKIT_PRIVATE_KEY` = المفتاح الخاص من ImageKit ← Developer options
4. امنح نفسك صلاحية الأدمن (بعد أن تسجّل في التطبيق مرة):
```bash
curl -X POST https://<مشروعك>.vercel.app/api/set-admin \
  -H "x-setup-secret: <كلمة السر>" -H "Content-Type: application/json" \
  -d '{"email":"بريدك@gmail.com"}'
```

### 5. البناء
كل push على `main` يبني APK موقّعاً (`ghanamaya-apk`) وملف AAB لـ Google Play (`ghanamaya-aab-for-play`) في تبويب **Actions**.

محلياً: `npm install && npx cap add android` ثم أضف `rgcfaIncludeGoogle = true` داخل `ext {}` في `android/variables.gradle`، ثم `npm run build:debug`.


## المرحلة الثانية: السوق
- الصور تُضغط على الهاتف (WebP، 1280px) ثم تُرفع إلى ImageKit بتوقيع من `/api/imagekit-auth` (للبائعين فقط).
- إذا كان رابط Vercel غير `ghanamaya.vercel.app` غيّر `API_BASE` في `www/index.html`.
- لا تحتاج أي فهارس مركّبة في Firestore: الفلترة والبحث على الجهاز من آخر 150 إعلاناً.

## المرحلة الثالثة: التواصل
- محادثة لكل (إعلان + مشترٍ) بمعرّف `listingId_buyerId`، مباشرة عبر Firestore.
- العروض: صالحة 24 ساعة، والطرف الآخر وحده يقبل أو يرفض أو يرد بعرض مقابل (تفرضه قواعد الأمان).
- الإشعارات: التطبيق يحفظ `fcmToken`، ودالة `/api/notify` ترسل للطرف الآخر بعد التحقق أنه طرف في المحادثة.
- الحظر: `users/{uid}/blocks/{otherId}` يمنع المحظور من بدء محادثة أو إرسال رسالة، ويخفي إعلاناته.

## المرحلة الرابعة: الطلبات
- الحالات: `pending → accepted → (paid لبنكك) → completed`، أو `rejected` / `cancelled`. كل انتقال مسموح لطرف محدد فقط في قواعد الأمان.
- السعر إما المعلن، أو عرض مقبول في محادثة المشتري (تتحقق منه القواعد من رسالة العرض نفسها).
- بنكك: رقم البائع يُنسخ في الطلب عند قبوله فقط، والمشتري يرفق الإشعار، والبائع يؤكد الوصول من تطبيق البنك.
- التقييم: مرة واحدة لكل طلب مكتمل، ومن المشتري فقط.

## المرحلة الخامسة: الإدارة
- لوحة الأدمن: `https://ghanamaya.vercel.app/admin/` (صفحة ويب منفصلة، لا تُضمّن في الـ APK).
  - أضف `ghanamaya.vercel.app` في Firebase ← Authentication ← Settings ← **Authorized domains** ليعمل الدخول بـ Google.
  - الدخول يتطلب صلاحية الأدمن (`/api/set-admin`).
- البلاغات تمر عبر `/api/report`: بلاغ واحد لكل مبلّغ وهدف، 10 يومياً، و3 مبلّغين مختلفين يخفون الإعلان تلقائياً.
- قرار واحد في اللوحة يغلق كل بلاغات الهدف: رفض (وإعادة نشر المخفي تلقائياً)، تحذير، إيقاف الإعلان، حذفه، إيقاف الحساب.
- التوثيق: البائع يطلب من حسابه، والأدمن يوثّق أو يرفض بسبب يظهر للبائع.
- الحساب الموقوف (`banned`) لا ينشئ إعلانات أو محادثات أو رسائل أو طلبات، ويرى شاشة الإيقاف في التطبيق.

## المرحلة السادسة: المحفظة الرقمية (OxaPay)
- الرصيد بسنتات USDT في `wallets/{uid}` (`balance` متاح، `held` محجوز)، وكل حركة في `transactions`. الكتابة من السيرفر فقط.
- **الإيداع:** `/api/wallet` (deposit) ينشئ فاتورة OxaPay، و`/api/oxapay-webhook` يتحقق من توقيع HMAC-SHA512 ويضيف الرصيد عند `Paid` مرة واحدة.
- **الشراء:** يُحجز المبلغ عند الطلب، ويُحرَّر للبائع بعد خصم العمولة عند تأكيد المشتري، أو تلقائياً بعد `releaseDays` (Vercel Cron يومياً)، أو يُسترد عند الرفض/الإلغاء. النزاع يجمّده حتى قرار الأدمن.
- **السحب (تلقائي بالكامل):** يُخصم فوراً ثم يُرسل آلياً عبر OxaPay Payout API (`api/_payout.js`). الحماية:
  - **سلامة الدفتر:** الرصيد يجب أن يساوي مجموع الحركات (عدا purchase) عند الطلب وقبل الإرسال، وإلا يُجمَّد.
  - **فترة أمان** مع تنبيه فوري وزر إلغاء: حساب جديد 48 س، إيداع حديث/عنوان جديد/مبلغ كبير 24 س، غير موثّق 12 س.
  - **حدود يومية** للمستخدم وللمنصة (التجاوز يُؤجَّل 24 س)، و3 طلبات سحب يومياً كحد أقصى.
  - **تجميد** (يحتاج الأدمن) فقط عند: خلل الدفتر، عنوان مشترك مع حساب آخر، فشل أو انقطاع OxaPay.
  - **قاطع دائرة:** 3 إخفاقات خلال 24 ساعة توقف السحب التلقائي، ومفتاح طوارئ في اللوحة.
  - **رمز المحفظة (PIN):** 6 أرقام مُجزّأة بـ scrypt في `walletPins/{uid}`، يُطلب في كل سحب. 5 أخطاء ⇒ قفل ساعة + إشعار. تغيير الرمز أو استعادته (بعد تسجيل دخول خلال 5 دقائق) ⇒ إيقاف السحب 24 ساعة.
  - **شاشة تأكيد:** العنوان كاملاً مقسّماً بتمييز أول وآخر 4 أحرف، مع إقرار إلزامي.
  - التنفيذ عند فتح أي مستخدم لمحفظته (`tick`) ومن الـ Cron اليومي. في وضع التجربة الإرسال محاكاة.
- متغيرات Vercel: `OXAPAY_MERCHANT_KEY`، `OXAPAY_PAYOUT_KEY` (للسحب التلقائي)، `OXAPAY_PAYOUT_NETWORK` (اختياري، افتراضياً `TRON`)، `OXAPAY_SANDBOX=true` للتجربة (احذفه عند الإطلاق)، `CRON_SECRET` (للتحرير التلقائي).
- لتفعيل الدفع بالمحفظة: لوحة الأدمن ← المالية ← حدد **سعر الصرف** (جنيه لكل USDT).

## الأمان
- المستخدم يكتب فقط حقول ملفه المسموحة؛ `verified` و `rating` لا يكتبها إلا السيرفر.
- حساب بنكك في `users/{uid}/private/payout` لا يقرؤه إلا صاحبه والأدمن.
- البائع لا يستطيع إلغاء صفة البائع من التطبيق، والتفعيل يتطلب اسم متجر وواتساب.
- الإعلان يُنشئه بائع مفعّل فقط، وصاحبه وحده يعدّله أو يعلّمه مباعاً أو يحذفه.
- البائع لا يستطيع فك إيقاف الأدمن عن إعلانه، ولا تمييز إعلانه بنفسه.
- الصور مقبولة من حساب ImageKit الخاص بالتطبيق فقط.
- كل مجموعات المراحل القادمة مغلقة تماماً حتى تُكتب قواعدها.

## اختبار سريع من السودان
افتح التطبيق **بدون VPN** وتأكد أن تسجيل الدخول وحفظ الملف يعملان؛ هذا يؤكد أن Firebase متاح للمستخدمين هناك.
